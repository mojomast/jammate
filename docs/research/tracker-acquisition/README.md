## Column semantics

`beats/<fixture>.csv`: one row per emitted beat event.
`eventSeconds` = backend's causal reported device time (else block start);
`availabilitySeconds` = device time at which `process()` returned (block end);
`latencySeconds` = availability − event.

`state/<fixture>.csv`: sampled to a *target* of ≤ 500 rows per fixture but every
beat block, silence-state transition, first and last block is kept, so some
fixtures exceed the target (see `stateRowsMax` / `stateRowsTargetExceeded` in
`summary.json`). Columns: block start/end, `bpm`, `phaseValid`, `silence`,
`confidence`, `onsetStrength`, `energyRmsDbfs`, `beatEvent`, `reportedSample`.

`fixtures.csv`: scorer result plus the independent replay (acquired, lock
timestamp, longest match run, longest tempo-agreeing run), the per-beat tempo
clause tally over the longest match run, trace evidence (median BPM, ratio to
local truth, silence blocks/seconds, mean phase), measured flags and the machine
reason. `agrees=1` means the replay verdict equals `scoreFixture`; the CLI exits
non-zero on any disagreement.

## Missing stays missing

Every optional measurement has a measured flag; when it is false the value is an
**empty CSV cell / JSON null**, and a measured zero is written as `0`. This
covers a failed lock's acquisition bars/seconds and lock timestamps, the BPM
relative error when there is no nominal BPM, and the BPM ratio / phase / octave
fields when there is no match or no phase-valid sample. Do not read an empty
cell as zero.
