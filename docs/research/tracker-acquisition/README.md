## Column semantics

`beats/<fixture>.csv`: one row per emitted beat event.
`eventSeconds` = backend's causal reported device time (else block start);
`availabilitySeconds` = device time at which `process()` returned (block end);
`latencySeconds` = availability − event.

`state/<fixture>.csv`: decimated to ≤ 500 rows per fixture but every beat block,
silence-state transition, first and last block is kept. Columns: block start/end,
`bpm`, `phaseValid`, `silence`, `confidence`, `onsetStrength`, `energyRmsDbfs`,
`beatEvent`, `reportedSample`.

`fixtures.csv`: scorer result plus the independent replay (acquired, lock
timestamp, longest match run, longest tempo-agreeing run), trace evidence
(median BPM, ratio to local truth, silence blocks/seconds, mean phase) and the
machine reason. `agrees=1` means the replay verdict equals `scoreFixture`.
