## Findings and fixes

| id | finding | fix |
|---|---|---|
| F1 | protocol declares a generated provenance marker must reject a real claim, but the manifest validator and gate eligibility ignored provenance | `glock/manifest.py` emits hard `provenance_contradicts_real` and excludes the recording from gate eligibility for markers `synthes*`, `generated`, `synthetic`, `machine-generated`, `not a human performance/recording`, `programmatic`, `karplus`, `rendered by` |
| F2 | `--traces-dir` could load a trace whose `backend`/`backend_kind` did not match the requested slot and still count for the real gate | `validate_trace` binds `expected_backend`/`expected_kind`/`expected_parent`; the CLI requires real kind for a real backend; `evaluate_gate` independently fails closed unless every gate score is exactly the requested backend with `backend_kind == "real"` |
| F3 | the derived candidate recorded an all-zero placeholder `tool_sha256` | the candidate hashes its actual producer source; `validate_trace` rejects all-zero placeholders (not merely non-64-hex) |
| F4 | the phase window was hard-coded to two bars | the window is `criteria.acquisition_window_bars * meter.beats_per_bar`; a no-op at the frozen default 2.0 |

## Trust boundary (explicit)

Classification, ownership, licence and provenance are **declared** fields. The
F1 check is a declaration-consistency rule and cannot mathematically attest that
the audio is a human performance; no offline byte inspection can. What the tool
*does* verify from the bytes is identity (sha256), sample rate, channels, sample
width, frame count and duration. A dishonest declaration is a trust-boundary
violation, and the protocol/READMEs say so explicitly rather than implying the
evaluator can prove human origin.
