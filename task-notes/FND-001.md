## Evidence

Two findings change what the orchestrator has to decide, and both are
prominent in the deliverables:

1. **⚠ The upstream history is missing.** `git log --format='%H %P' 88f7e7c`
   prints no parent; GitHub reports
   `"parents": [{"sha": "1d307b6ec61a5eea43c52c67e6b35f71d4dbe14e", ...}]`,
   and walking back reached 59 further ancestors before the unauthenticated API
   rate limit was exhausted (`rate_limit.core.remaining = 0`), so the true depth
   is ≥ 60 and **could not be determined here**. The tree is byte-identical, so
   the frozen-SHA guarantee holds; but `README.md` line 48 and
   `CONTRIBUTING.md` line 82 promise preserved history, and SPEC §25.2 requires
   preserving "notices **and history**". **Orchestrator decision required at
   G0** — keep the snapshot and point at the upstream SHA/URL, or re-import the
   ancestry before release. Not decided by me, not changed by me.

2. **⚠ Eight `references/*` submodules are declared but not pinned.**
   `.gitmodules` declares all eight (all `shallow = true`), and
   `references/README.md` line 3 calls them "Submódulos **pinados**", but
   `git ls-tree HEAD:references/` returns only `README.md` — and so does the
   upstream tree at `88f7e7c`. Therefore there is **no SHA for any reference
   project**, `git submodule update --init references/airwindows` (the command
   printed in that README) does not work, and the exact Airwindows revision the
   three ported effects came from is **unrecoverable**. The ports are legal
   under MIT, so this is a provenance gap, not an infringement — but it is the
   kind of gap an audit asks about. Each of the eight rows in
   `DEPENDENCIES.md` §5 reads `NO GITLINK IN TREE` rather than inventing one.
