# RT-005 — actual NAM PReLU/blending activation allocation repair

## Goal and base

Remove the per-model-sample activation allocation that RT-004 measured on the
real `GuitarCompanionProcessor::processBlock` for the A2-style
`wavenet_a2_max.nam` model, while preserving numerical behaviour exactly and
never mutating the pinned submodule.

## What was done

`patches/nam/activation-rt-alloc.patch` makes **three logical edits across two
files** that remove the per-sample allocation:

1. `ActivationsPReLU::apply(Eigen::MatrixXf&)` no longer copies
   `negative_slopes` into a local `std::vector<float>` on every call (the
   measured 1 heap `new`/call); it reads the preallocated member directly.
2. `GatingActivation::apply` and 3. `BlendingActivation::apply` (the
   non-`NAM_USE_INLINE_GEMM` branch) use explicit preallocated element-wise
   loops identical to the existing inline branch, removing reliance on Eigen
   evaluation temporaries.

A direct harness on the pinned headers proved the only allocating activation
operation is the PReLU vector copy; the RT-004 `BlendingActivation::apply` call
site was the inlined PReLU copy inside the blending template instantiation (the
blending combine expression itself allocated zero for the exact `Block`
destination types). The blending/gating rewrite is therefore a proven-equivalent
hardening of the non-inline branch, not a second measured allocation.

`cmake/nam-rt/NamRtPatch.cmake` is **extended** to SHA256-verify the pinned
activation inputs and the new tracked patch, apply both patches to the same
generated copy, and SHA256-verify all four generated files. RT-003 LSTM pins and
bytes are unchanged; both the root product and the standalone build compile the
same repaired bytes. In this environment the production and standalone
`nam_core` archives were **byte-identical** (`ad0ffbb3…`).

## Failures and corrections

- The first directly-instrumented activation test used a single-slope PReLU on
  multi-channel buffers. Upstream only guards that with a debug assert, so under
  `NDEBUG` both the original and patched code read out of bounds and diverged
  wildly (max_abs ≈ 1e25). The test now uses one slope per channel; the
  artifact was a test-input bug, not a repair defect.
- The first differential run fed `FLT_MAX`/`1e30` values plus `1e8` slopes and
  overflowed to Inf. Values are now bounded so the products stay finite.
- The activation-probe validator initially failed the expected capture-overflow
  in the positive controls. Capture overflow is now folded into the run status
  (a finding, never clean) and is only a hard failure for zero-expected runs.

## Review corrections — validator fail-closed hardening

The repair and overlay are unchanged (accepted): no overlay patch, generated
byte, pinned evidence or behavioral change. The following are validator/document
fixes only, with raw runs, `activation-probe-verification.json` and pins
preserved byte-for-byte.

- **F1 authoritative allocation accounting.** `check_activation_probe.py` now
  uses the authoritative `warm_alloc_cxx_total` / `warm_alloc_c_total` columns
  (which fold the nothrow/aligned `new` forms that have no plain column) as the
  zero test, with `regular <= total` as the required lower bound rather than
  equality. Cold has no authoritative total column, so its zero test sums the
  known forms. For zero-expected runs it now also enforces cold/warm
  free (`cxxdel`/`cxxdelarr`/`cxxdelsized`/`free`), lock
  (`lock`/`trylock`/`cond`/`unlock`) and all four alloc/lock overflow counters.
  A missing authoritative/pinned column is now a hard failure. `noopfree`
  (`free(NULL)`) is deliberately excluded and covered by accept tests. The
  authoritative split is now visible: LSTM uses C `malloc` (491520) and a2 uses
  C++ `new` (491520).
- **F5 runs-tree hygiene.** The validator fails closed on unexpected/stale
  variant or model directories, extra files (including extra CSVs) and stray
  root files; the exact 15-directory / 26-row matrix is required and no run is
  excluded.
- **F1/F5 tests.** `test_check_activation_probe.py` grew from 10 to **31**
  tests, adding authoritative-only (nothrow/aligned) allocations, cold
  alloc/lock overflow, cold regular alloc/free/lock, warm delete/lock/overflow,
  regular>total inconsistency, missing/malformed columns, deliberate noopfree
  acceptance, and unexpected directory/file cases.
- **F3 LF scope.** The overlay module comment now scopes the
  platform-independent byte claim to the accepted LF inputs; `check_patch.sh`
  adds a CRLF pinned-source fail-closed check (9 checks total), and the docs
  record that `.gitattributes` pins `patches/nam/*.patch text eol=lf`.
- **F4 source pin.** `predeclared.json` is unchanged and immutable; the docs now
  state that `source_pin.revision=677ce9f` is the processor source revision the
  probe archives were built from (identical to base `677727c`), not the RT-005
  worktree HEAD.
- **F2 probe provenance.** The docs state the runner executes prebuilt static
  probe binaries with no runtime archive substitution; the orchestrator's
  independent rebuild produced the same archive/probe hashes.
- **F6 counts.** Corrected to 5 retained standalone tests (4 unchanged +
  `nam_rt_patch_checks` extended) + 2 new = 7.

## Limitations (not claimed)

- Not a whole-program proof. Only the RT-004 predeclared five example models were
  measured; four example models outside the cap remain unmeasured and
  `SlimmableContainer` runs its default submodel only. **G1 remains partial.**
- `original` uses the read-only baseline shared archive while `lstm_only`/`new`
  use the RT-003 integration product shared archive; the strict
  single-archive-substitution contrast is `lstm_only` vs `new`.
- Capture overflow in the positive runs is expected and recorded; it can never be
  reported as clean.
- Differential is byte-identical for this compiler/Eigen/flag set; acceptance is
  the predeclared `1e-5` abs/relative budget, not cross-compiler bit-exactness.
  GNU `patch`/POSIX shell, Linux only; Windows and hosted-VST3 not measured.
- Non-device, single-threaded probe: no latency/dropout/device or Windows/ASIO
  evidence.
