# RT-003 — minimal real LSTM allocation repair

## Goal and base

Remove the two per-model-sample C-heap allocations RT-002 measured on the real
`GuitarCompanionProcessor::processBlock` (`calloc(48)` in
`nam::lstm::LSTMCell::process_`, `malloc(12)` in `LSTM::_process_sample`), while
preserving numerical LSTM behavior exactly and never mutating the pinned
submodule.

Worktree: `/home/mojo/projects/worktrees/RT-003-nam-lstm`
Branch: `wp/RT-003-nam-lstm` · Base: `af8b77a`
NAM pin: `1f42f88535884450104b8711d7595019afa0495b`
Depends on: `docs/research/PROCESSOR-RUNTIME-PROBE.md` (RT-002), SPEC.md §7.1/§18.1.

## What was done

Two edits in `NAM/lstm.{cpp,h}` (`patches/nam/lstm-rt-alloc.patch`): split
`_ifgo = _w*_xh + _b` into a `noalias()` product plus in-place bias (no Eigen
temporary), and return/accept the hidden state as `Eigen::Ref<const VectorXf>`
(a non-owning view) instead of a `VectorXf` by value. Floating-point op order is
preserved.

Applied via a configure-time generated copy of the pinned NAM tree under the
build dir (`cmake/nam-rt/NamRtPatch.cmake`, SHA256-pinned originals and outputs,
fail-closed), never touching `third_party/`. The root `CMakeLists.txt` NAM
section now points at the generated sources/include root; Dependencies stay on
the original pinned headers. `DEPENDENCIES.md` NAM row gained scoped patch
provenance; MIT notice unchanged.

## Failures / corrections

- First overlay attempt omitted the `LSTMCell::process_` *definition* signature
  change (header-only edit); the patched `nam_core` failed to compile. Added
  the third replacement; overlay hashes and pins updated.
- `file(COPY)` at configure time can be stale only if a source changes; the
  module declares `CMAKE_CONFIGURE_DEPENDS` on both pinned files and re-seeds
  from the originals on every configure, and the idempotence test covers it.

## Limitations (not claimed)

- Not a whole-program proof. Only the LSTM architecture/model RT-002 measured;
  WaveNet/A2/ConvNet/Slimmable were not measured. **G1 remains partial.**
- Probe NAM matrix is 48/96 kHz × 128/512; the (48 kHz) example model is not run
  at 44.1 kHz by the unchanged probe. `LSTM::process` is sample-rate independent.
- Differential is bit-exact for this compiler/flags; acceptance is the
  predeclared 1e-5 abs/relative budget, not cross-compiler bit-exactness.
- Non-device single-thread probe: no latency/dropout/device or Windows/ASIO
  evidence. Hosted VST3 unmeasured.
- The generated copy is an MIT derivative of the pinned NAM source; the MIT
  notice still applies. No new dependency.
