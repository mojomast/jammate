## Goal and base

Remove the two per-model-sample C-heap allocations RT-002 measured on the real
`GuitarCompanionProcessor::processBlock` (`calloc(48)` in
`nam::lstm::LSTMCell::process_`, `malloc(12)` in `LSTM::_process_sample`), while
preserving numerical LSTM behavior exactly and never mutating the pinned
submodule.

## What was done

`patches/nam/lstm-rt-alloc.patch` makes **five logical edits across two files**
(three in `lstm.cpp`, two in `lstm.h`) that remove the **two** allocations:
split `_ifgo = _w*_xh + _b` into a `noalias()` product plus in-place bias (no
Eigen temporary); make `LSTMCell::process_` take/define
`const Eigen::Ref<const Eigen::VectorXf>&`; return `get_hidden_state()` as
`Eigen::Ref<const Eigen::VectorXf>` (non-owning view) instead of a `VectorXf` by
value. Floating-point op order is preserved. The patch is zero-context (`-U0`)
so it contains no blank `" "` context lines and passes `git diff --check`.

Applied via a configure-time generated copy of the pinned NAM tree under the
build dir (`cmake/nam-rt/NamRtPatch.cmake`). The module SHA256-verifies the
pinned `lstm.{cpp,h}` **and the tracked patch itself**, wipes and re-copies the
whole `NAM/` tree (no stale private copies), applies exact replacements,
SHA256-verifies the generated output, and registers every copied file plus the
patch as `CMAKE_CONFIGURE_DEPENDS`. `third_party/` is never touched. The root
`CMakeLists.txt` NAM sources/include root point at the overlay; Dependencies stay
on the pinned headers. `DEPENDENCIES.md` NAM row records scoped provenance; MIT
unchanged.

## Failures / corrections

- First overlay omitted the `LSTMCell::process_` *definition* signature change
  (header-only edit); the patched `nam_core` failed to compile. Added the
  replacement; overlay hashes and pins updated. Correct logical-edit count is
  **five** (two allocations), not three.
- `patches/` first shipped with 6 single-space blank context lines, which
  `git diff --check af8b77a..<commit>` flagged. Regenerated the patch with
  `-U0`; it still applies cleanly and reproduces the overlay byte-for-byte.
- The module originally hash-verified only the pinned inputs, so editing the
  tracked patch was not detected. Added a declared patch SHA and a mutated-patch
  fail-closed test with clean pinned sources.
- The overlay originally copied the whole NAM tree without tracking the other
  files, so unrelated NAM changes could leave stale private copies. Now the
  whole tree is wiped/re-copied and every copied file + the patch is a
  `CMAKE_CONFIGURE_DEPENDS`; idempotence is tested on the same build dir and a
  scratch clone tests refresh/stale-removal.
- `compare_diff.py` previously accepted NaN/±Inf (`d > budget` is false for NaN
  and `inf > inf` is false) and trusted declared summaries. Rewritten
  fail-closed: metadata equality, exact six configs, contiguous coverage,
  `out_channels*block*(warm+1)` counts, binary finiteness, recomputed raw
  FNV/summaries, and `bit_exact` from raw bytes (not float equality). Added 19
  scripted unit tests.
- Standalone CMake had an implicit hardcoded `/home` fallback, an unconditional
  `-fPIC`, and silently skipped the probe check without python3; now explicit
  fatal default, PIC property only, and `python3` is required.

## Limitations (not claimed)

- Not a whole-program proof. Only the LSTM architecture/model RT-002 measured;
  WaveNet/A2/ConvNet/Slimmable were not measured. **G1 remains partial.**
- Only the `nam_core` target was built from the overlay here; the full
  JUCE/Standalone/VST3 product was **not** rebuilt. A full-product build is a
  separate future verification (future orchestrator).
- Probe NAM matrix is 48/96 kHz × 128/512; the (48 kHz) example model is not run
  at 44.1 kHz by the unchanged probe. `LSTM::process` is sample-rate independent.
- Differential is byte-identical for this compiler/flags; acceptance is the
  predeclared 1e-5 abs/relative budget (within-budget non-byte-identical passes
  with `bit_exact=false`), not cross-compiler bit-exactness.
- GNU `patch` / POSIX shell, **Linux only; Windows verification not done**.
- Non-device single-threaded probe: no latency/dropout/device or Windows/ASIO
  evidence. Hosted VST3 unmeasured.
- `NAM/dsp.h` and the `DSP` layout are unchanged, but the public
  `LSTMCell::process_`/`get_hidden_state` signatures changed: any *other*
  external consumer of `NAM/lstm.h` must be rebuilt. The read-only SharedCode
  archive does not consume that API (no LSTM symbols), so the prebuilt-archive
  probe result holds for this archive only.
- The generated copy is an MIT derivative of the pinned NAM source; the MIT
  notice still applies. No new dependency.
