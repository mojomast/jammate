# MOD-003 — Jam UI shell with fake data

## Goal
Build the dedicated Jam shell independently of analysis under explicit D7
permission for isolated UI work before full G1/G2.

## Base
`45fa333` on `wp/MOD-003-jam-ui`.

## Contract implemented
Message-thread value snapshot (`JamViewState`) and typed callback
(`JamUiIntent`). Silent state refresh; no engine or audio-device ownership.
All MOD-003 controls and telemetry, plus Break, Stop Next Bar, current bar/beat,
next event and advanced diagnostics disclosure. Clearly labeled simulation.
The fake 30 Hz provider lives entirely in the standalone dev wrapper.

## Tests
Actual GCC 14.2 Release compile/link against existing read-only JUCE GUI module
objects; Xvfb execution returned exit code 0. GUI verification passed silent
refresh, all controls, tap interval BPM, timer animation, immediate stop,
next-bar stop, four lock-state publications and layout bounds/non-overlap checks.
Resize sweep: 580/800/1000/1016/1280 × 600. Captures: 580 × 480, 1060 × 720, 640 × 540
(top and scrolled actions), and 1060 × 860 (diagnostics and stopped state).
Final log reports 21 intents. `git diff --cached --check` passed before commit.

## Evidence
Exact commands, screenshot descriptions and resolved local build issues are in
`docs/research/JAM-UI-SHELL.md`; final runtime output is in
`tools/jam-ui-preview/verification.log`. Six JUCE snapshots under Xvfb plus an
independent FFmpeg X11 desktop capture were visually reviewed.

## Known limitations
Preview is silent; no live guitar analysis, hardware metrics, latency validation
or production wiring. System fonts in preview; production font bridge already
exists in PluginEditor. Local CMake requires matching prebuilt Release JUCE
objects. Minimum validated preview size is 580 × 480; short layouts scroll.
Broader production Swing/Kit/Balance and device-health presentation remain
UI-001/AUDIO-001 scope. Windows and full-product builds were not run.

## Integration notes
Future owner publishes state and handles intents on the message thread. No
mock timer is present in the reusable component. Simulation wording is
intentional for this isolated shell. All changes are confined to owned paths.
