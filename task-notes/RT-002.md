# RT-002 — bounded processor runtime probe

## Goal and base

Obtain executed runtime evidence from the real pinned
`GuitarCompanionProcessor::processBlock` (no mock/stub/editor) for:

- cold and warm callback allocations/frees and callback locking in bounded
  cases, with inputs refilled outside the measured region;
- the scene-ready atomic flag consumed by the **processor-owned** `juce::Timer`
  through the genuine JUCE message loop, with the editor never created, and a
  no-audio differential that discriminates the processor Timer from the
  no-device fallback.

Branch: `wp/RT-002-processor-probe`. Base: `cd9f97f`.

## What was done

New, self-contained probe under `tools/processor-probe/**` (no shared source,
root/app/core CMake, ledger or other docs touched). It links **read-only**
against the prebuilt `libGuitar Companion_SharedCode.a` / `libnam_core.a` /
`libGuitarCompanionAssets.a` from
`/home/mojo/projects/guitars-build-resume/plugin`. Build flags come from that
build's `build.ninja`; the worktree `src/` include is prepended and the build
**fails closed** unless the pinned processor/drum/rt sources are byte-identical
to the main checkout the archive was compiled from (`source-pin.txt`).

Instrumentation is fixed-capacity and preallocated: global C++ `new`/`delete`
replacements, linker `--wrap` interposition of the C `malloc` family and
`pthread_mutex_lock`/`trylock`/`unlock`/`cond_clockwait`, all gated by a
`thread_local` arm flag with compile-time lock-free atomic assertions. The
max-lock publish is bounded (no CAS retry loop); `malloc(0)`/`realloc(ptr,0)` are
forwarded with exact C semantics; `free(NULL)`/`delete nullptr` are counted
separately. A mandatory self-check with **exact** expected counts proves both the
gate and the detectors before any processor measurement.

## Executed results

Environment: Debian 13, GCC 14.2, Release, no audio device, headless JUCE
message loop. Full identity/hashes in
`docs/research/PROCESSOR-RUNTIME-PROBE.md` and
`docs/research/processor-probe/`.

| Measurement | Result |
|---|---|
| Instrument self-check | PASS, exact counts (new/delete, malloc family, lock/unlock/trylock/cond) |
| Dry built-in chain, 18 cases (3 rates × 3 blocks × drums off/on; fresh input every callback; 1 cold + 256 warm each) | **0 allocations, 0 frees, 0 locks** cold and warm in every case |
| Built-in drum sampler actually renders | 256/256 warm blocks carried drum audio; playing `outRms` > identical-input stopped `outRms` in all 9 pairs; voice triggers recorded |
| `free(NULL)` no-op with drums playing | 1/block from the `processDrums` temporary `AudioBuffer`'s `juce::HeapBlock` destructor; counted separately, not a heap free |
| NAM `example_models/lstm.nam` via the real `loadModelAsync`/`processBlock` swap | **2 C-heap allocations per model sample** at 48 kHz (`calloc(48)` + `malloc(12)`, freed immediately) in `nam::lstm::LSTMCell::process_` and `LSTM::_process_sample`/`process`; 1.0/host sample at 96 kHz (resampled, same 2/model-sample) |
| NAM activation swap | occurred inside a dry warm block; not separately isolated (no callback allocation observed) |
| Hosted VST3 | unmeasured (no plugin present; not downloaded) |
| Scene flag → processor Timer | 11 real `processBlock` calls raised the flag with 0 alloc/free/lock; **no-audio 150 ms ⇒ not restored**; audio 100 ms ⇒ restored at ~32 ms; no-audio 400 ms ⇒ fallback restores at ~256 ms; editor never created; `stopSentBefore=0` |

`findings.json` is machine-verified; `run_probe.sh` exits non-zero unless every
check passes. `check_probe.sh` verifies malformed-CLI (exit 64) and output-failure
(exit 5) behaviour. G1 remains partial; the NAM violation does not by itself
close F2 (the engine MIDI path is separate and the internal sampler is
intentionally MIDI-free).

## Limitations / integration

- Non-device, single sequential thread: **not** latency/dropout/device or
  Windows/ASIO evidence. Per-block times are instrumented wall time, not CPU.
- NAM result is specific to the upstream example `lstm.nam`.
- `posix_memalign`/`aligned_alloc` called directly by shared libraries and
  `std::mutex` locked inside `libstdc++` are outside the interposed set; the
  callback path uses `juce::CriticalSection` and atomics.
- The scene attribution is a bounded differential + timing argument, not a
  breakpoint proof; reported at that strength only.
- Re-verify if scheduling clamps, the scene signal/timer, or the drum MIDI
  capacity change; `env-info.txt`/`manifest.sha256` pin code and artifacts.

**G1 remains partial:** bounded evidence, not a whole-processor or whole-program
allocation/lock proof. No 'safe' claim is made.
