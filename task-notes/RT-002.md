# RT-002 — bounded processor runtime probe

## Goal and base

Obtain executed runtime evidence from the real pinned
`GuitarCompanionProcessor::processBlock` (no mock/stub/editor) for:

- cold first-callback and warm callback allocations/frees and callback locking
  in bounded cases;
- the scene-ready atomic flag consumed by the **processor-owned** `juce::Timer`
  through the genuine JUCE message loop, with the editor never created.

Branch: `wp/RT-002-processor-probe`. Base: `cd9f97f`.

## What was done

New, self-contained probe under `tools/processor-probe/**` (no shared source,
root/app/core CMake, ledger or other docs touched). It links **read-only**
against the prebuilt `libGuitar Companion_SharedCode.a` / `libnam_core.a` /
`libGuitarCompanionAssets.a` from
`/home/mojo/projects/guitars-build-resume/plugin`, which already contains the
compiled processor and every pinned JUCE module. Build flags are read from that
build's `build.ninja`.

Instrumentation is fixed-capacity and preallocated: global C++ `new`/`delete`
replacements, linker `--wrap` interposition of the C `malloc` family and
`pthread_mutex_lock`/`trylock`/`unlock`/`cond_clockwait`, all gated by a
`thread_local` arm flag. Nothing is recorded unless armed; arming is a plain TLS
store. `free(NULL)`/`delete nullptr` are counted separately as no-ops. Caller
addresses are stored as file-relative offsets for `addr2line`.

A mandatory instrument self-check runs first and proves both that the gate
(disarmed → nothing) and the detectors (armed → correct categories) work; the
probe refuses to report processor results if it fails.

## Executed results

Environment: Debian 13, GCC 14.2, Release, no audio device, headless JUCE
message loop. Full identity, SHAs and artifacts in
`docs/research/PROCESSOR-RUNTIME-PROBE.md` and
`docs/research/processor-probe/`.

| Measurement | Result |
|---|---|
| Instrument self-check | PASS (gating + known new/delete, malloc family and mutex detection) |
| Dry built-in chain, 44.1/48/96 kHz × blocks 64/128/512 × drums stopped/playing (18 cases, cold + 256 warm each) | **0 allocations, 0 frees, 0 locks** in every case |
| `free(NULL)` no-op while drums play | 1/block from the `processDrums` temporary `AudioBuffer`'s `juce::HeapBlock` destructor; a defined no-op, counted separately |
| NAM `example_models/lstm.nam` via the real `loadModelAsync`/`processBlock` swap | **~2 C-heap allocations per model sample** (`calloc(48)` + `malloc(12)`, freed immediately) in `nam::lstm::LSTMCell::process_` and `LSTM::_process_sample`/`process` |
| Hosted VST3 | unmeasured (no plugin present; not downloaded) |
| Scene flag → processor-owned Timer, editor never created | section scene saved and applied; 11 real `processBlock` calls raised the flag with 0 alloc/free/lock; scene **not** applied before dispatch; applied only after a genuine bounded (100 ms) JUCE message loop; `getActiveEditor()==nullptr` |

## Limitations / integration

- Non-device probe on a single sequential thread: **not** latency, dropout,
  device or Windows/ASIO evidence.
- NAM result is specific to the upstream example `lstm.nam`; production captures
  and other architectures are unmeasured.
- Symbol-level interposition leaves libc/libstdc++-internal allocations and
  `std::mutex` locks inside `libstdc++` outside the measured set; the callback
  path was observed to use `juce::CriticalSection` and atomics only.
- Re-verify if scheduling clamps, the scene signal/timer, or the drum MIDI
  capacity change; the archive SHA in `env-info.txt` pins the code under test.

**G1 remains partial:** this is bounded evidence, not a whole-processor or
whole-program allocation/lock proof. No 'safe' claim is made.
